# 0.48.0：第一章实操与重战斗数据依赖

离线回放使用完整零售光盘和 Switch 构建的 ARM 游戏代码。新游戏从菜单进入，保留剧情影片、卷轴和章节页；没有写角色内存或强制跳关。在瀑布旁出现角色和血条后，测试只通过模拟 Xbox USB 手柄操作，并读取游戏自己的角色坐标。在相隔 144 次翻页的两轮测试中，24 帧中立输入均无位移；右推、松杆、左推，两轮均检测到方向相反的实际位移。第一次完整通过于第 1537 次观察到的场景缓冲翻转（retail2.log）。这验证了角色控制；未验证击败敌人、过关或实机性能。

本版支持剧情过场的纹理复制与顶点颜色、内核文件删除标记，以及已经退出但仍然有客体句柄的线程。活跃线程槽位现在可复用；旧句柄不会指向新线程。包内仍只包含演示数据，完整剧情使用单独只读光盘目录。宿主重放在临时容器中运行。

## 重战斗为什么不能直接把四个任务放到四个核

在原版自动演示 1801–1805 帧中，用同一份客体内存的第二个 Linux 映射追踪 ARM 游戏指令对 0x00400000–0x00FFFFFF 的快速访问。分别在四个任务的运行区间首写时保存页，离开任务时逐 32 位字比对。任务归属随原版线程、纤程和中断切换。下面是每帧两个任务都实际改变过的字数的范围：

| 任务 A | 任务 B | 共同写过并改变的字/帧 |
|---|---|---:|
| 渲染列表 1CA790 | 更新 1CB9A0 | 167–168 |
| 更新 1CB9A0 | 更新 151150 | 79–89 |
| 更新 1CB9A0 | 更新 0320E0 | 46 |
| 更新 151150 | 更新 0320E0 | 97–116 |
| 渲染列表 1CA790 | 更新 151150 / 0320E0（分别） | 0 / 0 |

这只是下界：不包含堆栈、VM 和其他地址段、恢复原值的写入，或读写发生在不同路径上的全部冲突；零不能证明独立。它已经足以排除无隔离地并行执行这四个完整任务。探针开启时的毫秒数不用于性能评估。

七个热点单元的私有 ARM 寄存器约定实验通过了 6144 个快照和 3018 次回调的差分，自动演示重战斗线程 CPU 从 5.808 降到 5.574 ms/帧。扩展到更多单元的实现触发原版内核停机；另试减少轮询、合并连续内存检查和改用指令跳转表，也未见足够整帧收益。这些实验没有进入 0.48.0 NRO。

主机线程 CPU 时间不等于 Switch 显示帧间隔。0.43.0 真机重战斗基线仍为 50.53 ms/帧；0.48.0 没有真机测量。

使用正式的 `replay.sh story` 独立从头启动，也在第 1537 次场景翻转通过。

每帧约 439、443 个绘制。单独再跑一次任务分账，两个窗口的任务合计
494.72、495.41 ms，均与外层线程时钟相符。渲染列表占 25.5%、25.3%，
