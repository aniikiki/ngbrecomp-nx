# 0.47.0：实测 Xbox 等待队列和任务耗时

真机最后一个有详细窗口的基线是 0.43.0：1801–1920 帧，50.53 ms 墙钟、49.68 ms 游戏线程、6.26 ms GPU。设备 CPU 1.02 GHz。CPU 与 GPU 重叠，不可相加。0.47.0 未上传，不能从以下数字估算新真机 FPS。

原始日志在本地私有构建目录 `build/switch-runtime/opt047/`。可复现的测试入口和测量范围见[离线回放说明](../../packaging/switch/perf/README.md)。光盘、生成的游戏代码和可执行包不包含在此报告中。

## 保留的改动

0.46 的调度器把还在等事件的 Xbox 线程当作就绪。检测实验（sched-audit.log / sched-park.log）分别记录恢复线程与尚未满足的等待条件。重战斗旧策略发生 329145 次切换，其中 210043 次切向未就绪的线程；新策略共切换 12423 次。绘制数分别为 80824 和 82821。跳过一次错误唤醒还避免了该线程立刻切回去，故切换减少数大于直接的不就绪命中数。本组计数回放有编译/诊断开销，不用它的时间推算收益。

在一场战斗里，相邻帧分配不同策略，每对的先后次序均衡。以 Linux 线程 CPU 时钟比较，从帧边界到下一次帧边界。原始帧：pair-sched.log。

|窗口|轮转 ms/帧|就绪选择 ms/帧|省时，8 帧分块重抽样区间|每帧绘制 旧/新|
|---|---:|---:|---:|---:|
|1681–1800|5.584|5.125|0.459 [0.337, 0.611]|488.5 / 489.3|
|1801–1920|6.488|6.088|0.401 [0.331, 0.481]|679.4 / 678.7|

第二次独立的同场交替试验使用最终调度代码。重战斗 6.086→5.696 ms/帧，省 0.390 ms，8 帧分块重抽样区间 [0.347, 0.435]，绘制 692.1/691.3 次每帧。开场 33–120 帧省时区间跨零，不能确认收益。此轮有自然结束回归并发运行；两轮不合并成真机预测。详见 repeated-trial.log。

无分组、从头独立运行，0.46/0.47 重战斗 6.003/5.962 ms（81254/81631 次绘制）；两次独立运行不复现相邻帧 6.2% 的全部差距。对应 exact-solo.log、sched-solo.log。0.47 开场 31–120 帧为 4.513 ms/帧。这里没有用线程 CPU 倒数冒充实际 FPS。

## 哪段游戏代码消耗了剩余时间

在原游戏任务入口读任务回调地址，切换线程和纤程时切换计时归属。运行中断和 DPC 单独记账。开场和重战斗中，独占账本分别合计 390.00、675.29 ms，最外层时钟为 390.09、675.37 ms。以下为游戏线程时间占比，并非 GPU 时间。

|任务回调|开场 31–120|重战斗 1801–1920|
|---|---:|---:|
|001CA790（有序渲染列表）|31.7%|31.7%|
|001CB9A0|18.8%|22.9%|
|00151150|10.5%|11.7%|
|000320E0|11.6%|11.3%|

0.43 真机重战斗 455 个挂起栈中，这四个任务分别出现于 175、87、70、54 个样本。旧版/设备采样和新版/主机计时不是同一个实验，但都指向同一组任务。二级离线计时见 children.log：重战斗中，渲染回调 001CB510 为 0.611 ms/帧；另外三条更新任务里的 001CC5A0、000298F0、00147DF0 各为 0.561、0.526、0.505 ms/帧。分账时替换父任务，不能再加回父项。渲染回调汇入 003078B0/00307B80 的模型路径。优先围绕共享模型提交和上述更新子函数做原生整段替代，比再尝试一种全局编译开关更有证据。

## 排除的候选

- 14 个热点单元用 devkitA64 自己的覆盖计数训练，与原 NRO 游戏对象同场对照。重战斗 6.152→6.075 ms，重抽样省时区间 [-0.030, 0.185]。不带入包。
- 变成固定全局内存并不能稳定改善整帧。四个单元重战斗 6.721→6.661 ms，区间跨零。
- 对实际 Switch libm 的 sin/cos 另做了实参回放：31–120 帧 318922 个结果、1801–1920 帧 672577 个结果逐位一致。即使只测这两个函数、忽略异常状态检查等集成成本，256 项每操作缓存也只省 0.009/0.011 ms 主机时间每帧。此处记录输入涉及的 CPU 时间，不从命中率（81.8%/71.7%）推定帧率。
- 另试 LLVM 明示寄存器文件和九种客体标量内存不重叠。八个单元使用 LLVM 与该标记的组合，在同场重战斗相对原 GCC 慢约 0.09 ms；这不是对所有 LLVM 方案的结论。
- Linux ARM 稀疏双重映射确实能在故障时回到原访问处理，但四个单元的实际游戏回放未显示整帧收益，不放入 Switch 异常路径。

离线 runner、分组重放和任务分账工具在 packaging/switch/perf。0.47.0 包使用正常 devkitA64 核心；4 项测试、单独桥接测试、NACP 版本及与 0.46.0 完全相同的 RomFS 均已核对。真机只新增每个采样窗口一行 SCHED，不需要额外 SD 临时文件。

完整无输入回归另用正式调度策略，从标题自动进入演示，记录到第 9240 次翻页，随后用图像采样验证已自然返回原版标题（natural.log）。
