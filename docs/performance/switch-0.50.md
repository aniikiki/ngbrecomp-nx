# 0.50.0-rc1：把 Xbox 寄存器留在 ARM 寄存器中

这是独立的 Switch 候选包，尚无实机 FPS。0.43.0 的真机重战斗仍是
50.53 ms/帧；60 FPS 的预算是 16.67 ms。下表只比较同场相邻帧的**宿主
ARM 游戏线程时间**，两组每帧都执行原版更新和绘制。

| 重战斗 1801–1920 帧 | 常规 → 寄存器约定 | 节省时间，8 帧分块重抽样区间 | 两组每帧绘制 |
|---|---:|---:|---:|
| 首次有正收益的对照，有其他进程活动 | 5.788 → 5.446 ms | 0.342 [0.121, 0.522] ms | 695.7 / 694.5 |
| 独立串行对照 | 5.518 → 5.063 ms | 0.455 [0.349, 0.533] ms | 694.0 / 693.0 |

第二轮开场和 1681–1800 帧的区间均跨零。不能将重战斗收益外推到全程。
更早的一轮在并发编译时也没有测到确定收益。

14 个编译单元共 3500 个原函数入口，内部保留七个 Xbox 整数寄存器和
客体内存基址。普通 C 函数、回调和外部入口通过汇编边界交换寄存器。
运行时仍在原先的位置轮询中断，保留原版栈校验。devkitA64 需要关闭
过程间寄存器分配才能保留一处真实的客体栈清理。候选包内的 14 个
游戏对象及入口与出口跳板均与离线对照所用文件逐字节一致；没有把
基线和实验两份代码一起打进 Switch 包。离线寄存器对照覆盖 96 个实际
树插入现场 × 64 个轮询相位，其中 3018 次回调边界的寄存器一致；
这不是对全部 3500 个函数的穷举验证。

用候选包的对象重新链接宿主服务后，客体文件、退交/重交内存、DPC 及
寄存器还原测试通过。从标题进入原版自动演示通过第 1920 帧；另从菜单
开新游戏，第一章两次停步和反向移动于第 1537 次场景翻转验证通过。
没有用这一结果代替实际关卡交战，也没有上传。NRO SHA-256：

## 为什么没有发布跨帧绘制缓存

重战斗 120 帧的两次追踪，跨帧模型索引内容、拓扑、顶点流地址及纹理等
绑定的匹配率均约 92%。这些比较**不包括顶点缓冲内容**。其中一次，
69,136 / 75,074 次匹配；在匹配子集中，相机矩阵和灯光表 100% 改变、
世界矩阵 92% 改变。缓存实验只复用了静态部分，仍提交每次绘制和动态
状态。渲染端抽查累计至少 53,248 次，完成 1920 帧；没有发现被抽查的
提交内容不一致。两次整帧实验没有可复现的收益，故不在候选包中。

进一步在原模型函数内部统计真正进入图形钩子的**调用顺序**：120 帧有
77,085 次提交、452,129 次拦截、342 种调用序列。相邻帧同一模型同次序
出现时，56,558 / 72,779 次调用位置序列相同（77.7%）。同一位置不保证
参数相同。设置顶点缓冲约 641 次/帧，单个索引绘制调用点约 605 次/帧，
单个绑定纹理调用点约 509 次/帧。仅知道其中一次绘制“上一帧也出现”
不足以删除它；此统计也不能把调用次数当成 CPU 时间。

**组合对照**：在同一场原版战斗内，常规寄存器约定并逐调用计时，
对比 14 单元 ARM 约定并轮换采样：5.752 → 5.079 ms/帧，节省 0.674 ms
（分块区间 0.490–0.808 ms），两组每帧分别绘制 677.9 / 676.8 次。
约 11.7% 是这两项改动一起实测的宿主游戏线程降幅。

## 绘制未通过测试的原因

两次独立的离线 Vulkan 回放在原画面实际绘制时做 GPU 查询。一轮 116 个
场景帧随机相位未控制、每七次可采绘制查一次，4,575 / 11,519（39.7%）
没有通过的像素样本。另一轮同时读取管线统计，共 11,394 次：
3,138 次裁剪阶段没有输出图元，334 次有图元但没有片元着色器调用，
1,071 次执行了片元着色器却没有通过的样本，6,851 次有通过的样本。
这是软件 Vulkan 的反馈；不能断言初代 Switch 有完全相同的比例。
“图元未输出”不等于已在游戏端证明整个模型在视锥之外。

## 两条更新任务共享的空间检测

0.50 候选包的 ARM 游戏线程得到 1,557 个栈样本，其中 1,554 个能读到
至少四层。两个不同的游戏更新分支经过 00035A00 → 00035B90 →
0013C050/0013C110 → 0013D330。后者出现于 113 个采样栈。另一次
120 帧的逐基本块计数中，0013D330 被调用 8,802 次，00140AF0 进入
105,624 次，98,914 次在初步空间检查后返回，其余 6,710 次进入细查。
其中 83,619 次走需要建立局部变换矩阵的候选分支。
这给了一个不同于减少绘制数的直接优化目标；调用数并非毫秒数。


## 能够在 CPU 上证明无可见图元的刚体

单独核对背面剔除：每个采样绘制用原管线，再用关闭背面剔除和颜色、深度、
模板写入的管线画一次。在 11,178 对中，2,963 对在两次查询中均没有
裁剪输出，没有一次因关闭背面剔除而恢复图元。其中 2,022 次使用刚体
固定功能格式 0x142 或 0x152。

在另一轮回放中，以实际上传的变换矩阵和整个顶点跨度计算局部包围盒。
11,254 次采样中，2,015 次可由同一个侧裁剪面证明全部在视野外。
每次仍执行原绘制，同时查询 GPU：这 2,015 次的输出图元数、通过的
像素样本数均为零。独立回放加入近/远裁剪面，11,253 次中侧面 2,032、
近面 10、远面 0，无矛盾。第三轮直接逐顶点测试侧面，11,133 次中
判出 2,062 次，仍无矛盾。只限固定功能刚体三角形，不按上一帧可见性跳过。

在不带 GPU 诊断查询的整场回放中，第一个包围盒实现在 1801–1920
帧交替实际省略绘制，实验组平均请求 691.2 次，省略 130.9 次。
这**没有**证明更快：渲染线程从本帧第一个 Draw 到 Present 入口的 CPU
时间为 3.341 → 3.425 ms，省时区间 [-0.284, 0.066] ms。这部分
工作发生在渲染线程，不能抵消此前重战斗的 49.68 ms 真机游戏线程时间。

对 00140AF0 的原生球体初筛另做实测，覆盖矩阵准备、局部空间变换及
六面快速拒绝路径。同一输入抽查超过 12 万次，与原客体的返回去向、
寄存器和所检查的内存一致。整帧交替对照 5.490 → 5.491 ms，
省时区间 [-0.135, 0.129] ms，未加入候选包。
